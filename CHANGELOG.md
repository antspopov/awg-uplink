# Changelog

Формат: секция `## X.Y.Z`. При обновлении через панель показываются все секции **между** текущей и новой версией.

## 1.3.1

### AmneziaWG
- При обновлении (панель и `--update-files-only`) модуль ядра всегда перезагружается: туннели останавливаются, `rmmod amneziawg`, `modprobe amneziawg`, затем туннели поднимаются снова.

## 1.3.0

### AmneziaWG 3.1
- Стек поднимается до AmneziaWG ≥ 3.1 (PPA или сборка с тега `v3.1.*`): модуль 3.1 принимает конфиги 1.x, 2.0 и 3.1 на одном ядре.
- Существующие `.conf` 2.0 не переписываются; конфиг 3.1 нельзя урезать до 2.0 — импорт 3.1 на стеке старше 3.1 отклоняется.
- Bootstrap и `--update-files-only` (в т.ч. обновление из панели) больше не пропускают апгрейд, если `awg-quick` уже есть, но линейка ниже 3.1.
- Панель: версия стека (tools/модуль) и бейдж протокола у каждого туннеля. Failover двух туннелей разных версий без изменений.

## 1.2.2

### MTProto
- Ссылки `tg://` и `t.me` генерируются в панели локально (без `mtbuddy links`), с учётом fakeTLS (`ee` + secret + hex домена маскировки).
- Хост в ссылке: домен Let's Encrypt при валидном сертификате; иначе ingress (или egress без split); для серых адресов (RFC1918, CGNAT) — внешний IP через curl, при неудаче — исходный серый.
- Dashboard API больше не подменяет ссылки с неверным `public_ip` из config.toml.

## 1.2.1

### Push-уведомления (ntfy)
- При self-signed TLS в URL подписки и QR подставляется IP ingress (или egress без split), а не домен — приложение ntfy корректно подключается к серверу с самоподписанным сертификатом.

### Панель
- Проверка обновлений: сравнение версии через GitHub Contents API, если CDN raw.githubusercontent.com отдаёт устаревший `VERSION`.

## 1.2.0

### Push-уведомления (ntfy)
- Self-hosted ntfy на шлюзе (HTTPS-порт 5001), автоматическая настройка topic и токена при bootstrap/update.
- Раздел панели «Push-уведомления»: QR-подписка (Android), URL сервера и topic, ссылки на приложения (Google Play, App Store, F-Droid).
- WebSocket и обычный режим (JSON stream) через nginx; порт **5001** в зарезервированных портах файрвола.
- Уведомления: туннели (failover, недоступность по ping, восстановление), ошибки обновления geo-списков, ошибки запуска сервисов.
- Обновление из панели (`--update-files-only`): установка ntfy и миграция nginx без переустановки конфигурации.

### Туннели
- Исправлено: выключение туннеля в UI не сохранялось (migrate больше не включает туннель при каждой загрузке `tunnels.json`).
- Предупреждение в UI, если отключение заблокировано (единственный туннель при маршруте через туннель).

## 1.1.8

- Поле ping и статус туннеля: значения по умолчанию в UI, учёт `.conf` в `/etc/wireguard/`.

## 1.1.6

### Firewall / UFW
- Исправлена ошибка UFW при новой установке: зарезервированные порты (SSH, веб-панель, MTProto и др.) всегда открываются на нужном интерфейсе; без `EGRESS_DEV` правила UFW не применяются преждевременно.

### Резервный туннель (два AWG)
- Второй туннель (`awg-uplink-2`): импорт `.conf`, включение/выключение, удаление конфига, перезапуск.
- Health-check (ping) по каждому включённому туннелю с настраиваемым интервалом.
- Автоматический failover: при потере связи на активном туннеле трафик переключается на второй; при восстановлении — обратно.
- Блокировка отключения/удаления единственного **рабочего** туннеля, если маршрут, georouting или MTProto завязаны на туннель.
- Синхронизация активного интерфейса с georouting (таблица 207, nft, `interfaces.env`).

### Панель и маршрутизация
- Статус маршрутизации при недоступном туннеле; блокировка georouting/MTProto без рабочего туннеля.
- Исправлена смена режима маршрутизации (`interfaces.env` / Path).
- UI: мерцающая кнопка «Импорт», блокировка «Перезапуск» без конфига, очистка черновика после импорта.

### Обновление из панели
- После self-update: применение туннелей, перезапуск ifaces/firewall/geo/DNS-таймеров (не только webui).
- В окне обновления — все секции CHANGELOG между версиями или список коммитов с GitHub.
